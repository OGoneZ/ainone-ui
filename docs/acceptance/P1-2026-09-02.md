## 有依据的偏离说明

1. **AC-P1-8 / AC-P1-11 未逐条实测**：P0 时已确认 omp 稳定、spawn 失败路径由 `bridge.ts` + `session.ts` 的 try/catch 覆盖；两个「错误态」分支为兜底性验收，未单独构造故障注入。若要严格达标，需补一次「把 adapter.args 改成不存在的模型」的运行时验证。
2. **AC-P1-9 / AC-P1-10 暂缓**：计划书制定时假设「自研 JSONL 分片解析 + 自研状态机」，故需要这两条测试。采用官方 SDK 后（DEC-7），分片切行由 SDK 的 `LineBuffer` 承担、状态流转由 SDK 承担，这两条测试的对象已不存在。替代方案：写一条「验证 bridge.ts 字节流 → SDK 能正确拼消息」的集成测试，纳入 P2。
3. **terminal 面板**：按 P0 结论（omp 在进程内执行 bash，不请求 ACP terminal 回调），terminal/* 降级为 S，P1 未实现——与计划书 P1 修订项一致。
