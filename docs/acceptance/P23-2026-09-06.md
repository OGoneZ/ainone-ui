## 已知缺陷（如实记录）

### P23-D1 · tauri-plugin-pty read-poll 模型导致 pty invoke 饿死（阻塞 kill/resize 复测）

- **现象**：GUI 冒烟中途起，`plugin:pty|*` 全部 invoke（get_all_pids/write/resize/kill）永久挂起（>10s 无返回），而自有命令 `terminal_default_shell_with_path` 秒回。关闭 tab 后 zsh 进程数不变。
- **根因分析**：插件 `read` 命令为 async command，内部 `reader.lock().await` 持锁后**阻塞 read**（portable-pty reader 无数据时阻塞）。前端 pty.ts 的 readData 用 `for(;;)` 连续 invoke read → 多个 read future 长期持有/排队。Tauri async command 共享 tokio runtime 线程池，read future 永不完成 → 后续 pty 命令（与 read 抢锁或排队）饿死。这是 tauri-plugin-pty 0.3 轮询式 read API 与多终端会话的结构性冲突，非本项目接线错误。
- **影响范围**：终端读数据本身正常（首个终端 shell 交互、pwd/stty 回显均正常，直到多终端并发后才触发饿死）；**单终端使用场景未观察到退化**。多终端并发下：显示层正常（xterm 收发走已建立的数据流），但新 pty 命令（含关闭 tab 的 kill）无法执行 → shell 进程残留。
- **缓解措施（本版已做）**：
  1. Rust 侧自建 track/untrack 登记表 + RunEvent::Exit 时对登记 pid 发负 pgid SIGKILL（terminal.rs on_exit_cleanup），应用退出兜底清全部 PTY 进程组（TERM 实测：退出后 5 个 zsh 全部消失，✅ 已验证）。
  2. 运行期关闭 tab 的 kill 依赖插件命令，在 P23-D1 场景下不生效——残留 shell 会在应用退出时被统一清理，但应用长驻期间残留。
- **后续修复方向**（超出本版范围，登记 ideas）：放弃插件 read 轮询，改用 `tauri::ipc::Channel` 自管 read 线程（参照 agent.rs pump_events 模式，read 阻塞移入独立 std::thread，channel 推送），kill/resize 走自有命令不与 read 共锁。改动集中在 terminal.rs + ipc/pty.ts，TerminalPanel 不动。

## 结论

P23 功能面（创建入口/窗格化/侧栏/索引/主题/单终端交互）全部达成且验收通过；多终端并发下的进程管理受选型插件的结构性缺陷影响（P23-D1），退出清理兜底已验证有效。缺陷已登记修复方向，不阻塞合并。
