## P32 相对 P30 的行为变化汇总

1. 流式期间**一律不收组**（原「尾部不可组块为界」在新 pending tool 到达时边界来回移动，独立↔组卡反复翻转 = 抖动主因）；收组统一推迟到 turn 结束一次性完成。代价：长 turn 流式期间多几行折叠行，换取零抖动。
2. 思考块 live 判定从「最后一个渲染项」改为「ms 未落且流式 turn 中」——思考后接工具不再闪收。
3. 工具块展开态跨分组迁移存活（稳定键）；用户手动操作后任何自动逻辑退场。
4. 含 diff 的组卡收组后默认展开（组级 groupDefaultOpen）；纯思考/无 diff 组默认折叠。
5. 全新自动滚动跟随 + 回到底部按钮（P30 前完全没有跟随能力）。

## 已知边界（如实记录）

- 组卡 body 仍为条件渲染（`{open && ...}`）而非常挂载：S1 流式不收组后，块在流式期间不再经历「独立↔组卡」翻转，turn 结束一次性收组时组卡是**新挂载**（按 groupDefaultOpen 计算初始值），用户在组内手动收起某块后把组收起再展开，该块回到 defaultOpen 而非保留手动态——组卡稳定键（首成员块派生）保证同组不重挂，仅组卸载（虚拟列表滚出窗口）时丢失。风险窗口小（滚出即重挂本就丢全部 state），未做组内常挂载（规格风险节的裁剪项，实测 DOM 压力优先级低）。
- 跟随恢复的「程序滚动守卫」依赖时间戳（150ms），极端慢帧（>150ms/帧）下跟随推底的 scroll 回声理论上可被误判——仅影响接管判定时机（多一次 following=true 置位），无可见症状；实机 WebKit 帧率远高于此。
- use-stick-to-bottom 的平滑弹簧滚动未引入（与虚拟列表不兼容）；当前推底为瞬时 `scrollTop` 赋值，长内容帧间隔大时观感是「跳」而非「滑」，与 ChatGPT/Claude 官方客户端行为一致。
