# P34 验收纪要：分屏可见性语义修复（2026-09-09）

> 分支：`zhubaoduo/perf/p34_visible_semantics`（worktree `.claude/worktrees/p32-perf-rendering`，基于 main @ 98d059c 后 rebase 到 5304e88）
> 性质：**P32 R7 语义缺陷回归修复**。规格：`docs/plan-p34-visible-semantics.md`

## 1. 事故与根因

**现象**：同页分屏（Ctrl+Shift+D/E）后焦点切到另一窗格，原窗格聊天区整块白屏。

**根因**（三层定位）：
1. `activeKeyOf` 是全局唯一焦点（单值），flexlayout 的可见性是 per-tabset（`positionTabPanels: visible = node.isSelected()`，dist 源码核实）——分屏时多个窗格的选中 tab 都在屏幕上，**失焦 ≠ 不可见**。
2. P32 R7 把 `useVirtualizer({ enabled: active })` 绑错对象：失焦窗格被冻结 → `calculateRange` 短路 → `getVirtualItems()` 空 → 可见区消息全部卸载 → 白屏。
3. 验收盲区：R7 验收只跑了 jsdom 单测，未复现真实多窗格布局。

**用户确认的正确模型**：屏幕上显示的窗格无论是否聚焦都应正常显示；优化只作用于屏幕外内容（同 tabset 被切走的 tab）；子进程/数据永不卸载。

## 2. 社区调研（四主题，详见规格书 §1）

| 来源 | 结论采纳 |
|---|---|
| VS Code（retainContextWhenHidden、issue #113507） | 内容模型保活、渲染按可见性分档是行业分界线 |
| Chrome 节流（background_tabs、timer-throttling-88） | 元素级 display:none 不停 rAF；整窗隐藏平台原生兜底 + 本仓 turn 结束 flush 兜底已有 |
| tanstack virtual（#823/#697、官方文档） | enabled 是官方解法，但绑定对象必须是容器可见性而非焦点；useCachedMeasurements 不采用（enabled 已覆盖） |
| 多窗格应用（tmux/kitty/React Activity） | 无「后台 pane 降频」先例；不自建降频机制 |

## 3. 修复内容（R1，单 commit）

- `layout.ts`：新增 `visibleKeysOf()` 纯函数——每 tabset 选中 tab 集合（与 flexlayout 可见性判定同源）。
- `App.tsx`：`syncFromModel` 同步 `visibleKeys`；`factory` 给 ChatPanel 传 `visible` prop。
- `ChatPanel.tsx`：props 增 `visible`（默认 true），`useVirtualizer({ enabled: visible })`；`active` 焦点语义全部保留（打字机暂停、window 事件路由、onActiveSession）。
- 语义矩阵：可见+焦点=正常；**可见+失焦=正常渲染（本次修复）**；不可见（同 tabset 切走）=冻结（R7 收益保留）；焦点行为不变。

- `ChatPanel.p34.test.tsx` +5（useVirtualizer mock 透传 enabled 真实语义）：

  - active=false 不影响 enabled（两信号正交）。
