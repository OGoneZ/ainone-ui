# 需求-验收对齐审计（Gap Audit）

**日期**：2026-09-08
**性质**：一次性审计报告，非开发基线。逐条列出「需求/规格书 vs 验收报告/代码现状」的偏离、缺口与风险，供所有者检验并逐条决定处置方式。
**方法**：通读 docs/ 全部 24 份计划/规格书与 18 份验收报告，用 git 提交链、tag、Cargo.toml、代码 grep 逐条核实。每条均有可点击的证据锚点。

**使用方式**：每条有唯一编号（DEV-/GAP-/GUI-/NOSPEC-/BASE-/MISC-）。读完直接在 §8 决策汇总表填写决定；也可以在条目行内批注。

**处置选项词汇**：
- **补验**——补做验收/手测，闭环该条
- **登记延期**——在对应基线文档变更记录写明延期与新期限
- **登记取消**——正式宣布不做，删除期待
- **接受现状**——该偏离合理，把理由固化进文档即可
- **需实机操作**——只有所有者本人能做（动真实环境）

## 6. E 类：基线承诺与成功指标

### BASE-01 · tag 记录不实（🔴 最严重）→ ✅ 已裁决关闭（2026-09-08）
- **事实**：P3/P4/P5/P6 验收报告结尾均写「打 tag v0.3.0~v0.6.0」，docs/plan-v2.md:8 也声称这些 tag 存在。**实际 `git tag` 只有 v0.1.0、v0.2.0**。
- plan-v2.md:20-22 又改口径承诺「功能合入即 patch 递增（v0.3.1、v0.3.2…）」——从未执行，package.json / tauri.conf.json 版本号至今 **0.2.0**。
