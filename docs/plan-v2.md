### 0.3 v1 遗留技术债（本计划必须消化）

| #   | 遗留项                                                       | 溯源                | 消化期   |
| --- | ------------------------------------------------------------ | ------------------- | -------- |

| D-2 | 点击历史会话每次新开 Tab、同一 sessionId 可开多个子进程      | v1 未覆盖的 bug     | P4（M）  |

### 0.4 两个 bug 的根因定位（P4 修复依据）

1. **点历史会话新开窗口**：`src/App.tsx` 的 `openFromHistory()` 无条件新开 Tab 且不去重；同一会话可叠加多个 Tab，各自 spawn 子进程，上下文分叉。
2. **历史聊天记录加载不出来**，三个根因叠加：
   - `src/acp/session-core.ts` 的 load 分支把回放的 update 直接 `drainQueue()` 丢弃，UI 拿不到任何内容（当年 AC-P2-8 按计划降级的技术债）；
   - 协议层天生不完整：ACP `session/load` 回放只含 agent 侧内容（assistant/thought/tool），**不含用户消息**——即使不丢弃也拼不回完整对话；
   - 消息数据只存在于 React 内存，应用重启即失忆。
   - 结论：修 bug 不能只靠协议回放，必须引入本地消息日志（见 DEC-9）。

## 2. P4 · 现代聊天体验（含 bug 修复）

**方向**：对话区是产品的脸。用户消息在右、agent 在左；每个 harness 用自己的 logo 头像；thinking 是浅色小字、完成后自动折叠；空会话时输入框居中打招呼，开始聊天后过渡到底部。

### 2.1 功能规格

**F-4-1 气泡化对话布局（M）**

- 用户消息右对齐气泡；agent 消息左对齐 + **agent 头像**（取 adapter 的 logo 资源）
- 头像按 harness 区分：OMP / Pi / Claude Code / OpenCode / Codex 各自 logo；adapter 注册表新增 `logo?: string` 字段；未配置 logo 的 adapter 显示名称首字母圆形占位
- thinking 块位于其所属 assistant 回复内部（不再是独立消息条目），小字号浅色样式

**F-4-2 thinking 折叠交互（M）**

- 流式进行中：thinking 浅色小字展开显示
- thinking 结束（首条正文/工具出现，或 turn 结束）自动折叠为一行「已思考 N 秒」，点击展开/收起
- 一轮回复中多段 thinking（工具间穿插）每段独立折叠

**F-4-3 历史回填（M，消 D-1）**

- 引入**本地消息日志**：每会话一份 JSONL（`appDataDir/sessions/<sessionId>.jsonl`），按序持久化全部消息（user/assistant/thought/tool）
- 用户消息发送时写入；assistant/thought/tool 在 turn 结束时批量落盘
- 恢复会话 = `session/load`（agent 恢复上下文）+ 读本地日志回填消息列表（GUI 呈现完整对话）
- 双源冲突原则：**本地日志为单一真源**，ACP 回放仅供 agent 内部上下文、不参与渲染
- 日志损坏/缺失时降级为「上下文已恢复，历史消息未找到」提示行，不阻塞续聊

**F-4-4 会话去重与单实例（M，消 D-2）**

- 点击历史会话：该 sessionId 已有打开 Tab → 激活既有 Tab；否则才新开
- 保证任一时刻一个 sessionId 至多一个活跃子进程

**F-4-5 输入框居中欢迎页（M）**

- 无消息时（新建会话，或恢复但日志为空）：输入框垂直居中 + 欢迎语（「你好！我可以帮你做什么？」）+ 几条可点击的建议 prompt
- 首条消息发出后：输入框动画过渡到底部固定位置，消息流出现
- 动画用 CSS transition（transform/opacity），不引入 JS 动画库

**F-4-6 输入区升级（S）**

- 多行 textarea 自动增高（Enter 发送 / Shift+Enter 换行），替代单行 input
- 顶部保持 harness 上下文徽标，用户始终知道在和谁说话

**F-4-7 slash command 自动补全（M）**

- 输入框内输入 `/` → 弹出该 harness 的命令选项列表（命令名 + 一行描述 + 参数 hint）
- 列表随输入前缀实时过滤；键盘 ↑↓ 选择、Enter 确认、Esc 关闭；鼠标点击同样可选
- 选中后命令名（含 `/`）回填输入框，光标留在命令后供补参数
- 数据源：ACP `session/update · available_commands_update` 通知（harness 主动上报，P0 已存档样例）——按会话存入全局 store，UI 不维护命令清单
- 协议事实与对策：OMP 的该通知在**首次 prompt 后**才到达（报文存档可证），新会话空态时清单为空 → 按 adapter 缓存最近一次清单持久化，新会话先用缓存、收到通知后覆盖
- 不实现命令的本地执行——命令始终作为普通 prompt 文本发给 harness，由其自行解释（单一交互范式）

**F-4-8 全局状态外提（M，为 P6 铺垫）**

- 引入 zustand（v1 DEC-6 已选型但从未引入）：把 ChatPanel 内的 messages/busy/权限状态外提为按会话 key 的全局 store，使「非活跃 Tab 的运行状态」可被侧栏读取

### 2.2 关键技术决策

| #      | 决策                                           | 理由                                                                                                        |
| ------ | ---------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| DEC-9  | 历史回填用本地消息日志，不解析 ACP 回放        | 回放不含 user 消息（协议边界）；各 harness 本地会话文件格式互异，逐个解析不可持续；本地日志一套方案覆盖全部 adapter。反对项「等 ACP 规范出 history 拉取」——规范演进时间不可控，产品不能等 |
| DEC-10 | 日志由前端 TS 经 Tauri fs API 写入，不加 Rust command | 业务逻辑全部在 TS（v1 DEC-3）；JSONL 追加写简单，TS 单测可覆盖                                        |
| DEC-11 | UI 改版不引入组件库，延续手写 CSS + CSS 变量   | 现有 data-theme 变量体系可用；引组件库违背最小改动纪律                                                  |

### 2.3 验收标准

- **AC-P4-1**：发送一条消息 → 用户消息出现在右侧气泡；agent 回复在左侧且带该 harness 的 logo 头像 → 通过
- **AC-P4-2**：切换到另一个 harness 的会话 → 头像随之变为对应 logo → 通过
- **AC-P4-3**：agent 思考过程流式出现时为浅色小字展开态；正文开始后自动折叠为「已思考 N 秒」；点击可展开/收起 → 通过
- **AC-P4-4**：会话中告知 agent 暗号 → 重启应用 → 点击历史列表该会话 → **不新开 Tab**（若已打开则激活既有 Tab）且消息区出现完整历史对话（含右侧用户气泡与左侧 agent 气泡）→ 通过
- **AC-P4-5**：恢复会话后向 agent 询问暗号 → 正确复述（回归 v1 AC-P2-4）→ 通过
- **AC-P4-6**：新建会话 → 输入框居中 + 欢迎语；发送首条消息后输入框平滑过渡到底部 → 通过
- **AC-P4-7**：输入 `/` → 弹出命令选项列表（含名称与描述）；继续输入可过滤；↑↓ 键移动高亮、Enter 选中回填、Esc 关闭；鼠标点击同样可选 → 通过
- **AC-P4-8**：同一 harness 新开一个会话直接输入 `/` → 列表仍可用（来自 adapter 级缓存）；另一 harness 的会话列表内容不同（各 harness 命令集独立）→ 通过
- **AC-P4-9**：5000 条消息会话的日志回填 < 2 秒且渲染流畅（回归 AC-P3-5）→ 通过
- **AC-P4-10**：全部测试绿（含新增 vitest 单测：日志读写、历史去重）→ 通过

### 2.4 P4 完成后的用户能力

- 一眼分清谁在说话（气泡 + harness logo 头像）
- thinking 像主流产品一样折叠展示
- 点历史会话不开新窗、能找回完整聊天记录
- `/` 一键唤起当前 agent 的命令面板，键盘鼠标皆可选
- 空会话有居中欢迎页，输入框有现代过渡动画

## 3. P5 · 工作区（Workspace）模型

**方向**：左侧从「平铺会话列表」升级为「工作区分组」——像 VS Code 的工作区概念，但只显示工作目录本身，不做目录树。同一工作目录下的 session 归集为一组，互相独立。

### 3.1 功能规格

**F-5-1 工作区实体（M）**

- 新实体 `Workspace { id, name, cwd, createdAt }`，存储于 appDataDir
- 左侧边栏改为「工作区分组列表」：工作区为父级（文件夹图标 + 名称 + cwd），其下挂该工作区的 sessions（按 mtime 倒序）
- 只显示工作目录本身，不显示子级目录（明确不做目录树）
- 空工作区显示为单行父级标题

**F-5-2 新建会话流程改造（M）**

- 新建 session 时必须先选择工作区（弹层列出全部工作区 + 新建工作区入口）
- 新建后左侧出现对应工作区父级标题，后续 session 收集在其下
- 不同工作区的会话完全独立

**F-5-3 工作区管理（M）**

- 添加工作区：本地目录选择对话框（Tauri dialog 插件）
- 移除工作区：其下会话移入「未归组」区（数据不丢失）
- 工作区右键菜单：在此工作区新建 session / 重命名 / 移除
- 会话移动到其他工作区（S）

**F-5-4 存储与迁移（M）**

- session 索引新增 `workspaceId` 字段
- 旧索引迁移：存量会话按 cwd 自动聚类归入对应工作区；无 cwd 信息的归入「未归组」
- cwd 重复的工作区按规范化路径去重

### 3.2 验收标准

- **AC-P5-1**：新建工作区（选择某目录）→ 在其中新建会话并发一条消息 → 左侧出现该工作区父级，会话列于其下 → 通过
- **AC-P5-2**：同一工作区再新建一个会话（可换 harness）→ 两个会话并列显示在该工作区下，互不干扰 → 通过
- **AC-P5-3**：两个不同工作区各一个会话 → 分组显示，互不混入 → 通过
- **AC-P5-4**：右键工作区 → 新建会话 → 该会话自动归属此工作区，无需再选 → 通过
- **AC-P5-5**：移除工作区 → 其下会话移入「未归组」，数据不丢失 → 通过
- **AC-P5-6**：从 v0.4.x 升级 → 存量会话按 cwd 聚类归组，无丢失 → 通过
- **AC-P5-7**：全部测试绿 → 通过

### 3.3 P5 完成后的用户能力

- 按项目目录组织所有 agent 会话
- 右键工作区直接开新会话，建会话永远知道自己在哪个目录
- 升级不丢历史

## 4. P6 · 会话运行状态与灵动性

**方向**：多会话并行是本产品的核心形态（PS-4），侧栏必须一眼回答「哪些 agent 在干活、哪些完成了、哪些在等我」；空态体验对齐 ChatGPT/Gemini。

### 4.1 功能规格

**F-6-1 会话状态指示（M）**

- 每个会话条目显示状态：
  - `working`——清晰但不刺眼的小动画（呼吸/旋转），正在工作
  - `done`——静态完成标志（任务结束，动画停止）
  - `awaiting_input`——等待用户（权限请求中 / 等待回复），脉冲图标
  - `idle`——空闲灰点
- 状态数据源：P4 外提的 zustand store（不活跃 Tab 的状态也可读）
- 切换 Tab 不中断其他会话的状态显示

**F-6-2 运行中会话强调（S）**

- working 状态的会话条目加高亮边或徽标；权限请求到达时该条目闪烁一次

**F-6-3 空态欢迎页升级（M）**

- 继承 P4 欢迎页并升级：按时间段的问候语（早上好/下午好/晚上好）
- 建议 prompt 按 harness 各不相同，点击直接填入并发送

### 4.2 验收标准

- **AC-P6-1**：会话 A 发送长任务 → 侧栏 A 条目出现清晰的 working 动画 → 通过
- **AC-P6-2**：任务完成 → 动画停止变为静态 done 标志 → 通过
- **AC-P6-3**：A 运行期间切换到空闲的会话 B → A 的 working 动画持续显示（状态不因切换 Tab 丢失）→ 通过
- **AC-P6-4**：agent 请求权限 → 侧栏对应条目显示 awaiting_input 状态 → 通过
- **AC-P6-5**：空会话显示时间段问候语 + 建议 prompts，点击建议直接发送 → 通过
- **AC-P6-6**：全部测试绿 → 通过
