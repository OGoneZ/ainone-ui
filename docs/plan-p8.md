## 0. 调研结论（2026-09-02 实测，决定性）

用 bun 探针 `tools/spike/e2e-p8-capabilities-probe.ts` 对 `claude-agent-acp` 实测（复用生产 session-core），结论：

| 探测 | 结果 | 影响 |
|---|---|---|
| `usage_update` 通知 | ✅ 发，`{used, size, cost}` | IDEA-002 上下文占用/token/成本**数据源坐实** |
| `session/fork` | ✅ 真实现，返回新 sessionId | IDEA-005 分叉**协议可行**（但「从历史点」仍需客户端重放） |
| `providers/list` | ✅ 返回 `providerId/apiType/baseUrl`，**无模型名** | IDEA-002「当前模型」**拿不到模型名**，只能 apiType+baseUrl |
| `current_mode_update` | ❌ 不发（样本空） | 「当前 mode」此 harness 无数据源，降级 |
| `file 回滚能力` | ❌ 协议无此方法 | IDEA-006「回滚文件修改」必须外置（git 快照），ACP 无解 |

**由此定死的三项架构决策**：

- **DEC-13**：IDEA-002「当前模型」字段的来源 = adapter 启动配置（`args` 里 `--model`），ACP 只补 apiType/baseUrl。协议不提供模型名，不硬造。
- **DEC-14**：IDEA-005 分叉 = `session/fork`（`sessionId + cwd`，从**当前状态** fork）；「从历史点 fork」留待「客户端本地重放」子项，不在首期。
- **DEC-15**：IDEA-006 的「回滚文件修改」（情况二）= 外置 git 快照，ACP 无能力；「只回滚上下文」（情况一）走客户端重放 + 截断本地日志。

## 2. P8.1 · 第一批

### F-8-1 IDEA-004 会话↔harness 绑定收尾（M）

- 会话行 leading 槽位显示**该会话的 harness logo**（复用 P7 F-7-3 头像体系，按 `adapter_id` 解析）
- hover/聚焦会话行时，`title` 显示 harness 名称（如「Oh My Pi」，与 logo 同来源）
- 点击历史会话 → 打开时**用会话自己绑定的 adapter**（`adapter_id`）驱动，而非当前选中项（当前实现已如此，本条为验收锁定）
- 后台并行策略：非活跃会话的子进程**默认常驻**（当前已实现）；新增「空闲超时回收」为 S 项（默认不回收）

**验收**：
- **AC-P8-1**：同一工作区下 3 个不同 harness 的会话 → 每条会话行显示各自 harness logo，hover 显示对应 harness 名 → 通过
- **AC-P8-2**：点击某会话 → 打开的 ChatPanel 用该会话 `adapter_id` 对应 harness（而非其它）→ 通过
- **AC-P8-3**：3 个会话并行工作，切换 Tab 各自 status 不丢、logo 不串 → 通过

### F-8-2 IDEA-001 批注式引用提问（M）

- 选中 assistant 消息（Markdown 渲染后）一段文字 → 该文本旁生成批注卡
- 批注卡内可填疑问/评论；一次回复内可连续框选多处，各生成独立批注卡
- 全部完成后「发送」一次 → 组装成一条请求：`被引用原文 + 各条疑问`
- 引用拼装（DEC-13 关联）：纯文本拼接进 `prompt`，格式如下（确定性，可单测）：
  ```
  [引用 1] <原文片段>
  疑问：<批注内容>
  ---
  ```
- 与 steering 兼容：运行中发送批注 → 打断当前 turn 后新发起（复用现有打断队列）

**验收**：
- **AC-P8-4**：选中一段 assistant 文字 → 出现批注输入，填入疑问后发送 → user 气泡中可见「[引用 N] + 原文 + 疑问」的组装文本 → 通过
- **AC-P8-5**：同一回复框选 2 处 → 各自批注，发送后组装出 2 段引用 → 通过
- **AC-P8-6**：运行中发送批注 → 打断当前 turn 并发起新 turn（回归 steering）→ 通过
- **AC-P8-7**：批注组装为纯函数（`composeQuotedPrompt`），vitest 覆盖多段/空批注边界 → 通过

> **待定项留到实现**（来自 ideas.md IDEA-001 待定 1/3/4/7，不阻塞排期）：批注卡视觉承载形式（悬浮/侧栏/行内）、历史回填后批注挂载、光标映射回原文。实现时按 P7 消息 hover 操作行样式就近承载。

## 3. P8.2 · 第二批

### F-8-3 IDEA-003 文件引用（M）

- 输入栏上方「添加文件」按钮 + 拖拽到对话框区域，二者同一条路径：文件加入「待发送附件」集
- 附件胶囊列表（文件名 + × 移除）
- **传路径语义（DEC）**：文件作为**绝对路径**传给 harness，由 harness 自行读取（不注入内容、不占客户端上下文）。格式 `@file:/abs/path`
- 附带一个「注入内容」开关（S 项，默认关）：开启时用 fs 读文件内容拼入 prompt（烧 token，用户自行权衡）

**验收**：
- **AC-P8-8**：点「添加文件」选 1 个文件 → 输入栏出现附件胶囊 → 发送 → user 气泡含该文件绝对路径引用 → 通过
- **AC-P8-9**：拖拽文件到对话框 → 高亮反馈 + 释放即附上（与按钮同路径）→ 通过
- **AC-P8-10**：附件 × 移除 → 发送不含该文件 → 通过
- **AC-P8-11**：路径引用组装为纯函数（`composeFileReference`），vitest 覆盖多文件/绝对路径校验 → 通过

### F-8-4 IDEA-002 元数据侧栏（M）

- 右侧新增可折叠第二侧栏，展示当前会话元数据：
  - **上下文占用**：`used / size` + 百分比进度条（来源 `usage_update`，已实测）
  - **token 用量**：`used`（含 cost，有则显示）
  - **session ID**（本地）
  - **工作区 cwd**（本地）
  - **harness/apiType**（adapter + `providers/list` 的 `apiType/baseUrl`）
  - **模型**（adapter `args` 里 `--model`，若配置；DEC-13）
- 数据流：`session-core` 扩展 `dispatchUpdate` 捕获 `usage_update` → 外发为 `Outgoing` 事件 → 存入 zustand（按 tabKey），侧栏订阅
- 默认折叠，展开开关持久化

**验收**：
- **AC-P8-12**：会话运行中 → 右侧栏上下文占用进度条随 `usage_update` 实时更新 → 通过
- **AC-P8-13**：显示 sessionId / cwd / apiType / 模型（若有配置）四项，值与实际一致 → 通过
- **AC-P8-14**：侧栏可折叠，折叠状态重启后保持 → 通过
- **AC-P8-15**：`usage_update` 提取为纯函数（`extractUsage`），vitest 覆盖 used/size/cost 提取与空值 → 通过

## 4. P8.3 · 第三批

### F-8-5 IDEA-005 会话分叉（M）

- 在某条 assistant 消息 hover 操作行提供「从这里分叉」入口
- 分叉实现 = `session/fork`（`sessionId + cwd`，从当前状态 fork，DEC-14）
- 分叉出的会话作为新条目出现在侧栏，标注「从 XX 分叉」；独立 `session_id` + 独立消息日志
- 首期**不做**「从任意历史点 fork」（需客户端重放，列为后续）

**验收**：
- **AC-P8-16**：运行中的会话点「分叉」→ 侧栏出现新会话（标注来源），fork 出的新 sessionId 非空且可继续对话 → 通过
- **AC-P8-17**：新分支继续对话 → 原会话不受影响 → 通过
- **AC-P8-18**：fork 封装纯函数 `forkSession`（session-core 内）+ e2e 探针（真实 harness fork 返回新 sessionId）→ 通过

### F-8-6 IDEA-006 消息回溯（M，仅上下文回滚；文件回滚为 S+外置）

- 用户消息 hover 操作行提供「回溯到这里」入口
- **情况一（M）只回上下文**：以该消息之前的历史为基底，`session/load` 恢复 + 本地日志截断到该点，之后消息丢弃
- **情况二（S）回上下文+文件**：情况一之上，对上轮文件修改做 `git` 快照回滚（DEC-15）；破坏性操作须二次确认
- 回溯前显著提示；情况二额外危险确认

**验收**：
- **AC-P8-19**：回溯到第 N 条 → 上下文与消息列表截断到 N 之前，之后对话消失 → 通过
- **AC-P8-20**：截断为纯函数（`truncateToMessageIndex`），vitest 覆盖边界（N=0 / 越界）→ 通过
- **AC-P8-21**：（S）文件回滚走 git 快照，回滚前有二次确认 → 通过

> **待定**（来自 ideas IDEA-006）：文件快照粒度（每 turn 一次 / 每文件写一次）、回滚可逆性。实现时以「每 turn 结束后 git commit（若在 git 仓库内）」为最简起步。
